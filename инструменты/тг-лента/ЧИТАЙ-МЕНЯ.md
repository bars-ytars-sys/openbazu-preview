# Автоматическая лента Telegram → сайт

Источник: публичный канал `https://t.me/s/openbaza`.
Страница: https://открытьбазу.рф/news
Редактор: https://tilda.cc/page/?pageid=269069409

Лента и блок «Свежее из канала» на главной читают
`https://cdn.jsdelivr.net/gh/bars-ytars-sys/openbazu-preview@main/assets/news/feed.json`.
Перепубликация Тильды для новых постов не нужна.

## Автоматизация

В репозитории `bars-ytars-sys/openbazu-preview`:

- `.github/workflows/telegram-news.yml` запускается раз в сутки в 23:55 по Москве (20:55 UTC) и вручную через Run workflow; новые посты за день попадают на сайт одним обновлением;
- `инструменты/тг-лента/` содержит сборщик, обновляющий скрипт, тест и список исключённых номеров;
- корневой `правки.txt` содержит рабочий переключатель `лента-автообновление = да` и два фильтра;
- права `contents: write` нужны для коммита только `assets/news`;
- бот и Telegram-токен не требуются.

GitHub может задерживать запуски расписания. Статус и ручной запуск:
https://github.com/bars-ytars-sys/openbazu-preview/actions/workflows/telegram-news.yml

Сборщик собирает 60 допустимых новостей во временной папке. Пустые, неполные,
повторённые, устаревшие ответы или ошибки картинок отменяют обновление.
Опросы и кружки исключены по прежнему заданию. Скрытые отрывки не публикуются
в JSON и логах. Сохраняются прежние картинки, чтобы открытые страницы не ломались.
После коммита сбрасывается кеш jsDelivr и проверяется совпадение всей ленты.
Если сброс кеша не удался, следующий запуск повторяет его даже без нового коммита.

GitHub Pages не пересобирается от коммита `GITHUB_TOKEN`; боевая Тильда читает
Git непосредственно через jsDelivr и от сборки Pages не зависит.

## Локальная проверка и выкладка

```powershell
python инструменты/тг-лента/тест_сборщика.py
python инструменты/тг-лента/обновить-сайт.py --repo .news-automation-repo
```

`.news-automation-repo` — отдельный клон репозитория, без полной пересборки демо.
Выкладывать только проверенные `assets/news`, скрипты, workflow и минимальный файл
флагов. Не использовать общий `выложить-демо.sh` для автоматизации: он переносит
все страницы демо, часть которых не согласована для живого сайта.

## Остановка и откат

Остановить через Disable workflow на странице Actions либо изменить
`лента-автообновление = нет` **в корне GitHub-репозитория** и закоммитить.
Локальная строка сама не синхронизируется с GitHub.
Для возврата данных сначала остановить workflow, вернуть `assets/news/feed.json`
из предыдущего коммита, запушить и выполнить:

```powershell
python инструменты/тг-лента/обновить-сайт.py --repo .news-automation-repo --purge
```

Перед первым включением сохранена прежняя лента в `документы/лента-05-10/feed-before.json`.
